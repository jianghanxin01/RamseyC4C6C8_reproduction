RamseyC4C6C8: Windows reproduction guide

Purpose and requirements
This package supports the finite computations for R(C4,C6,C8)=12. It contains
nine CNF inputs, nine archived RUP proofs, three Windows x64 executables and
complete C++14 sources. The mathematical reductions remain in the paper.
Run the supplied programs on Windows x64 after extracting the whole archive
to a writable directory. No Python, separate SAT installation, Visual Studio,
LaTeX or network connection is required for the supplied executables. The
launchers use Windows' built-in command processor and Windows PowerShell.

1. Locate the package root
The correct directory contains these files and folders directly:
  VERIFY_ALL.cmd       REPRODUCE_ALL.cmd
  CHECK_HASHES.cmd     BUILD_ALL.cmd
  bin/                data/               src/
  docs/               reports/            vendor/
  instances.json      SHA256SUMS.txt
Keep all supporting launcher files and the directory structure intact.
The bin directory contains RamseyInputs.exe, RamseySolve.exe and RamseyRup.exe.
Do not run directly inside the ZIP viewer. This is the online reproduction
package; manuscript and reviewer-supplement files are supplied separately.

2. Check the distributed files
Double-click CHECK_HASHES.cmd. The final result should be HASH CHECK PASSED.
This verifies the bytes listed in SHA256SUMS.txt; it does not prove the graph
encoding or the RUP certificates. Results and rebuilt binaries are excluded
from the immutable distribution manifest.

3. Verify all archived proofs
Double-click VERIFY_ALL.cmd. It first reconstructs and compares all nine input
clause multisets, including auxiliary clauses and repeated clauses. It then
checks all nine archived proofs. Accept the full run only if it finishes with:
  SUCCESS: all nine input audits and 9 selected certificate check(s) passed.
The workflow exit code must be 0. A partial run is not a 9/9 result.

4. Reproduce all inputs and proofs
Double-click REPRODUCE_ALL.cmd. It reconstructs all nine inputs in a fresh
results directory, compares them with the archive, generates new proofs, and
checks each new proof against the same newly generated CNF. The full-run
success line is the same 9-certificate line above, with workflow exit code 0.
Solver exit 20 means UNSAT; a case is accepted only after the independent
checker also returns 0. Solver exit 10 means SAT; other solver results fail
the workflow. New CNF ordering, proof bytes, lengths and timings can differ
from the archive without changing the accepted mathematical result.

5. Use PowerShell, a selected case, or another executable directory
Open PowerShell in the package root. Run each command separately and inspect
its exit code immediately afterward:
  .\CHECK_HASHES.cmd --no-pause
  $LASTEXITCODE
  .\VERIFY_ALL.cmd --no-pause
  $LASTEXITCODE
  .\REPRODUCE_ALL.cmd --no-pause
  $LASTEXITCODE
The --no-pause option only removes the final keypress prompt.
A shorter first trial is:
  .\VERIFY_ALL.cmd --no-pause --case B-leafK4
  .\REPRODUCE_ALL.cmd --no-pause --case B-leafK4
Both launchers still audit ALL NINE inputs. The --case option selects only
one proof for checking or regeneration, so success reports 1 certificate.
Omit --case for full 9/9 verification or reproduction. Supply --case only once.
The accepted IDs are:
  48T1, 48T2, H10-I3, H10-K2_K1, H10-P3,
  B-root-1, B-root-2, B-leafK4, B-C9.
Stable numbers in case IDs and data paths identify files, not release versions.

6. Read and retain the results
Each run prints a fresh results/verify_TIMESTAMP_RANDOM/ or
results/reproduce_TIMESTAMP_RANDOM/ directory. It contains:
  summary.txt          overall status, selected cases and executable directory
  inputs.log/json      input reconstruction and comparison results
  ID.rup.log           proof-checking result for each selected case
  ID.solve.log         solver output (reproduction only)
  generated/ID.cnf      reconstructed input (reproduction only)
  generated/ID.rup      fresh proof (selected reproduction cases only)
The launchers return 0 for success, 1 for a computation or proof failure, and
2 for an argument, installation or startup error. On failure, retain the
complete result directory and report the command and exit code. A solver
message, an old report or an incomplete proof file is not a successful run.

7. Rebuild from source (optional)
Install Visual Studio with Desktop development with C++ and a Windows SDK.
The supplied component build commands use optimized x64 C++14 and the /MT
static C/C++ runtime. Then run from the package root:
  .\BUILD_ALL.cmd --no-pause
  $LASTEXITCODE
A successful build returns 0 and places all three executables in rebuilt_bin/.
Source copies and compiler logs are saved under results/build_TIMESTAMP_RANDOM/.
Check the freshly built programs explicitly:
  .\VERIFY_ALL.cmd --no-pause --bin rebuilt_bin
  .\REPRODUCE_ALL.cmd --no-pause --bin rebuilt_bin
The --bin path is relative to the launcher directory; absolute paths also work.
Recompiled executable hashes may differ with compiler and build settings.

8. Evidence and scope
The archived validation reports describe earlier recorded runs and retain
their original numerical results and binary identities. They do not by
themselves certify a later build. reports/release_validation.json records
checks performed for this release and the newly compiled solver's identity.
For your own reproduction claim, retain the logs from your own complete run.
See docs/WINDOWS_COMMANDS.md for command details, docs/INPUT_SEMANTICS.md for
encodings, and docs/PROVENANCE_AND_LICENSES.md for source and licence notices.
These nine finite cases do not replace the paper's case-coverage arguments,
recompute cited external extremal values, or constitute a formal verification
of the entire Ramsey proof. The checker itself is not formally verified.
The programs and explanations were prepared with OpenAI Codex assistance;
different programs are not claimed to have independent human authorship.
