# C++14 输入重建与核验说明

`RamseyInputs.exe` 从图论条件出发，重新生成第 53 版九个原始算例的完整 CNF，并与随附 CNF 的全部子句比较。比较包括边数计数器、字典序辅助变量以及低度顶点的路径见证辅助变量。本程序不依赖 Python、SAT 求解器或第三方程序库。

这里核验的是“计算输入是否确实对应规定的图论条件”。不可满足性还需要由独立的 RUP 核验器确认；九个算例覆盖论文所需情况的数学归约，仍由论文中的人工证明承担。本程序没有将整篇论文形式化。

## 一、直接运行

下面假定最终程序包包含 `bin` 和 `data` 两个目录。在该程序包目录内打开 PowerShell，输入：

```powershell
.\bin\RamseyInputs.exe --all --data .\data
```

九个算例均应显示 `PASS`，最后显示 `ALL REQUESTED INPUT CHECKS PASSED`，退出码为 0。开发电脑上的完整运行约需十秒；其他电脑的时间可能不同。

如需同时保存报告及重新生成 CNF：

```powershell
.\bin\RamseyInputs.exe --all --data .\data --generate .\fresh_inputs_1 --report .\input_report_1.json
```

所有输出文件必须是新文件。程序拒绝覆盖已有文件，因此原始 CNF、RUP 和已有报告不会被替换。重复运行时，请换一个输出目录或报告名称；报告所在的上级目录需预先存在。

仅核验某个算例，或同时核验若干指定算例：

```powershell
.\bin\RamseyInputs.exe --case B-root-1 --case B-root-2 --data .\data
.\bin\RamseyInputs.exe --list
```

不读取原有 CNF，直接从条件重新生成输入：

```powershell
.\bin\RamseyInputs.exe --all --generate .\fresh_inputs_2 --generate-only --report .\generation_report_2.json
```

最后一种方式只表示“已经生成”，报告状态为 `GENERATED_NOT_COMPARED`，不表示完成了与原始输入的比较。新输入可以交给另一个 SAT 求解器重新计算。本程序本身不进行 SAT 搜索。

## 二、算例编号和输出文件

| 算例编号 | 内容 | 变量数 | 子句数 |
|---|---|---:|---:|
| `48T1` | 第一个 31 边宿主图的箭头性质 | 31 | 5,135 |
| `48T2` | 第二个 31 边宿主图的箭头性质 | 31 | 4,567 |
| `H10-I3` | 十点图，根顶点三邻点之间没有边 | 521 | 17,903 |
| `H10-K2_K1` | 十点图，根顶点三邻点之间恰有一条边 | 521 | 17,903 |
| `H10-P3` | 十点图，根顶点三邻点构成三点路径 | 521 | 17,903 |
| `B-root-1` | 十二点蓝图，选定最小度为 1 的根顶点 | 1,672 | 453,834 |
| `B-root-2` | 十二点蓝图，选定最小度为 2 的根顶点 | 1,553 | 462,022 |
| `B-leafK4` | 十二点蓝图，规定一个末端四点完全块 | 1,335 | 35,107 |
| `B-C9` | 十二点蓝图，规定一个九圈 | 1,085 | 362,228 |

`48T1`、`48T2` 是保留的历史算例 ID，不是页码或数学变量。数学宿主图的定义见 `INPUT_SEMANTICS.md`；论文中的记号以正文为准。

新文件使用扁平名称，例如 `fresh_inputs_1\B-root-1.cnf`。新文件保留原有变量编号和每个子句的出现次数，但对子句及子句内的文字排序。因此新文件的 SHA256 可以不同于原始文件；程序比较的是完整的子句多重集。原始 CNF/RUP 文件继续保留原有哈希值。

程序严格检查 DIMACS 格式、变量范围、子句数以及结尾的 0，拒绝重复的子句内文字和永真子句。重复的整条子句保留，比较时不擅自去重。普通空白、注释、子句顺序和子句内文字顺序不会影响比较。

退出码 0 表示全部指定操作成功；1 表示至少一个算例失败；2 表示命令行、报告写入等顶层错误。若程序退出码不是 0，不应把中途出现的部分 `PASS` 当成九个算例全部通过。

## 三、使用 VS 2026 编译 Release 版本

安装 Visual Studio 的“使用 C++ 的桌面开发”组件及 Windows SDK，然后在源码目录运行 `BuildRelease.cmd`。也可以打开 `RamseyInputs.vcxproj`，选择 **Release / x64** 后生成。

项目使用 VS 2026 的 `v145` 工具集；命令脚本会自动寻找已安装的 Visual Studio x64 编译器。生成文件位于源码目录下的 `bin\x64\Release\RamseyInputs.exe`。采用 C++14、优化选项 `/O2`、静态运行库 `/MT`，并将编译警告视为错误。编译和运行均不需要 Python。

如果已经打开“x64 Native Tools”命令窗口，也可以执行：

```text
cl /std:c++14 /O2 /MT /EHsc /W4 /WX /utf-8 /DWIN32_LEAN_AND_MEAN /DNOMINMAX RamseyInputs.cpp /FeRamseyInputs.exe
```

## 四、核验范围

第 53 版的低度算例核验程序仅机械检查图约束和边数约束，字典序及路径辅助部分依赖源码审查。本版将这些部分一并完整重建，实际九例比较均已通过。

仍需区分三件事：输入编码正确、RUP 证书正确、论文的数学归约覆盖所有情况。本程序解决第一项，独立 RUP 核验器解决第二项，论文的人工推导解决第三项。引用自 McKay 表格的极值数不属于这九个计算证书的核验范围。
