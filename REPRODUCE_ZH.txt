RamseyC4C6C8：Windows 复现操作说明

用途与环境
本包用于复核 R(C4,C6,C8)=12 论文中的九项有限计算，含九份 CNF 输入、
九份原始 RUP 证明、三个 Windows x64 程序及完整 C++14 源码。
完整解压后，在可写目录中运行。运行随包 EXE 不需要 Python、另装 SAT
求解器、Visual Studio、LaTeX 或联网；启动脚本使用 Windows 自带的
命令处理器与 PowerShell。数学归约及人工证明仍须阅读论文。

1. 找到正确目录
解压后的 RamseyC4C6C8_reproduction 根目录直接包含：
  VERIFY_ALL.cmd       REPRODUCE_ALL.cmd
  CHECK_HASHES.cmd     BUILD_ALL.cmd
  bin/                data/               src/
  docs/               reports/            vendor/
  instances.json      SHA256SUMS.txt
bin 中应有 RamseyInputs.exe、RamseySolve.exe 和 RamseyRup.exe。
保留其他配套启动文件及整个目录结构。不要在 ZIP 浏览窗口中直接运行。
本包是网上公开的复现材料；论文稿子与审稿补充材料另行提供。

2. 检查文件完整性
双击 CHECK_HASHES.cmd，末尾应显示 HASH CHECK PASSED。
此步骤核对 SHA256SUMS.txt 列出的文件字节，不能代替输入与证明检查。
运行生成的结果及自行重编译程序不列入原始发行文件的校验清单。

3. 检查全部原始证明
双击 VERIFY_ALL.cmd。程序先重建并比较全部九份输入的子句多重集，
包括辅助变量子句和重复子句；通过后，依次检查九份原始 RUP 证明。
完整验收应为 9/9，流程返回值为 0，末行必须是：
  SUCCESS: all nine input audits and 9 selected certificate check(s) passed.
只完成部分案例不能算全部通过。

4. 从头生成输入和新证明
双击 REPRODUCE_ALL.cmd。程序在新结果目录重建全部九份输入，与原始
输入比较，再逐项求解；每份新证明均针对同一份新生成的 CNF 独立检查。
完整验收仍是上述 9 份证明全部通过的成功行，流程返回值为 0。
求解器返回 20 表示 UNSAT，随后检查器也必须返回 0；仅显示 UNSAT
不能算成功。新输入的子句顺序、新证明的字节、长度和耗时可与原文件不同。

5. 在 PowerShell 中运行或先试一个案例
在本包根目录打开 PowerShell，逐条执行；每次立即查看返回值：
  .\CHECK_HASHES.cmd --no-pause
  $LASTEXITCODE
  .\VERIFY_ALL.cmd --no-pause
  $LASTEXITCODE
  .\REPRODUCE_ALL.cmd --no-pause
  $LASTEXITCODE
--no-pause 只取消末尾按键等待。较短的单案例试运行：
  .\VERIFY_ALL.cmd --no-pause --case B-leafK4
  .\REPRODUCE_ALL.cmd --no-pause --case B-leafK4
即使指定 --case，两个入口仍检查全部九份输入，但只检查或生成一份证明；
此时成功行中的证明数量是 1。完整验收须去掉 --case。该参数只能用一次。
可用案例 ID：48T1、48T2、H10-I3、H10-K2_K1、H10-P3、B-root-1、
B-root-2、B-leafK4、B-C9。ID 和数据路径中的旧数字是稳定文件标识。

6. 查看结果与处理失败
每次运行均在 results/ 下新建 verify_时间戳_随机数 或
reproduce_时间戳_随机数 目录，完成时会显示位置。保留该次完整目录。
  summary.txt          总体结果、案例及使用的程序目录
  inputs.log/json      输入重建与比较结果
  ID.rup.log           各案例证明检查结果
  ID.solve.log         求解输出（仅重新生成证明时）
  generated/ID.cnf     新生成的输入
  generated/ID.rup     选定案例的新证明
启动流程返回 0 表示成功，1 表示计算或证明检查失败，2 表示参数、安装
或启动错误。失败时保留命令、返回值和日志；旧报告、部分证明文件、
求解器单独显示 UNSAT，都不能代表本次运行成功。

7. 可选：重新编译
安装 Visual Studio 的“使用 C++ 的桌面开发”工作负载及 Windows SDK。
编译脚本使用 x64 C++14 优化构建和 /MT 静态 C/C++ 运行库。在根目录执行：
  .\BUILD_ALL.cmd --no-pause
  $LASTEXITCODE
成功应返回 0，rebuilt_bin/ 中应生成上述三个 EXE。源码副本及编译日志
保存在 results/build_时间戳_随机数/。随后明确使用新编译的程序验收：
  .\VERIFY_ALL.cmd --no-pause --bin rebuilt_bin
  .\REPRODUCE_ALL.cmd --no-pause --bin rebuilt_bin
--bin 相对路径以启动脚本目录为基准，也可填绝对路径。编译器及设置不同，
EXE 哈希可能不同。编译成功本身不能代替输入与证明检查。

8. 验证记录与适用范围
原验证记录保留的是较早运行的数值及当时程序哈希，不能自动证明后来
编译的程序已通过。reports/release_validation.json 单独记录本次发行
完成的检查和新编译求解器的身份。报告自己的复现结果时，应保留自己运行
得到的完整日志。命令细节、编码说明及来源许可见 docs/ 中对应文件。
这九项计算不替代正文的案例覆盖论证，不重算引用的外部极值数据，也不
表示全文或检查程序已由证明助手形式化验证。程序和说明使用了 OpenAI
Codex 辅助；不声称不同程序具有相互独立的人类作者。
